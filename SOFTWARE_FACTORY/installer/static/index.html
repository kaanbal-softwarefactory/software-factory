Un servicio, no un plugin

El agente (Acuaponsito Runtime, puerto 4600) es independiente del instalador: login propio, memoria propia, WebSocket en tiempo real. Sus claves viven en ~/.acuaponsito/ y al desplegar la célula también se integran al cluster como Secret kaanbal-ai-providers.

Al terminar aquí, el flotante te acompaña en toda la plataforma — y en cualquier app tuya con una línea de código.

Dominio propio + CloudflareRecomendado

Tu plataforma nace lista para el mundo: dominio real con TLS, sin abrir puertos, sin IP pública y sin tocar el router. Mientras tu equipo esté encendido, Cloudflare enruta tu dominio hacia él.

📘 Guía · apuntar tu dominio a Cloudflare (una sola vez)
  1. Entra a dash.cloudflare.com → Add a site y escribe tu dominio.
  2. Cloudflare te dará 2 nameservers (ej. xxx.ns.cloudflare.com). Cópialos.
  3. Ve a donde compraste el dominio (GoDaddy, Namecheap, etc.) → Nameservers / DNS → reemplaza los actuales por los de Cloudflare.
  4. Espera a que Cloudflare marque el dominio como Active (minutos u horas).

No necesitas crear registros A ni el wildcard a mano: el instalador crea el túnel y los DNS por ti (*.tudominio y tudominio como CNAME al túnel). Así cada app que lances obtiene su subdominio automáticamente.

📘 Guía · crear el API Token con los scopes correctos
  1. Ve a dash.cloudflare.com/profile/api-tokens → Create Token → Create Custom Token.
  2. Agrega estos permisos exactos:
    • Account · Cloudflare Tunnel · Edit
    • Zone · DNS · Edit
    • Account · Account Settings · Read
  3. En Account Resources incluye tu cuenta; en Zone Resources, tu dominio.
  4. Continue → Create Token y cópialo (solo se muestra una vez).
📘 Guía · dónde está tu Account ID
  1. En dash.cloudflare.com, entra a tu dominio.
  2. En la barra lateral derecha (o en la URL dash.cloudflare.com/<ACCOUNT_ID>/...) copia el Account ID.

💡 ¿Dudas con algún paso? Pregúntale a tu agente (el flotante 🌱): tiene la API conectada y te guía en dónde hacer clic exactamente.

🐙 GitHub GitOps · el repo que ArgoCD reconcilia
Repo GitOps (fuente de verdad)
    📘 Guía · crear el PAT
    1. Classic (recomendado para bootstrap): github.com/settings/tokens → scopes repo, workflow, read:org, user:email.
    2. Debes ser admin de la org para que el instalador cree los repos core.
    3. Pega el token → Validar → elige la org. Si faltan repos, se crean al desplegar.

    Repos core: infra-gitops (manifiestos/ramas), kaanbal-api, kaanbal-console. Ahí vive el GitFlow de ambientes.

    🐳 Docker Hub registro de imágenes de tus apps
    📘 Guía · crear el Access Token
    1. Ve a app.docker.com/settings/personal-access-tokens → Generate new token.
    2. Permisos Read & Write (para publicar imágenes de tus apps).
    3. Copia el token (dckr_pat_...) — solo se muestra una vez.

    Se guarda como secret regcred en el cluster para que tus apps hagan pull/push.

    🔐 Tailscale VPN privada · acceso seguro sin exponer
    📘 Guía · crear el OAuth client
    1. Ve a login.tailscale.com/admin/settings/oauth → Generate OAuth client.
    2. Scopes: Devices · Write y DNS · Read (para el operator).
    3. Tu DNS suffix está en admin/dns (algo como tailXXXX.ts.net).

    Habilita el tier privado: servicios internos (Vault, BD) accesibles solo por tu tailnet, sin salir a internet.

    🛡️ Exposición de Kaanbal Console quién puede llegar al panel

    Esto solo decide cómo se publica el panel. La exposición de cada app que despliegues (pública, VPN o solo interna) se elige después, app por app, dentro de la consola.
